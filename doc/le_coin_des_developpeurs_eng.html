Developer corner

WhiteCat is free software, released under the GNU GPL v2. Created by Christoph Guillermet (2009-2016), it has been taken over and modernized since 2026 by Jacques Bouault (arpschuino.fr): move to SDL2 and RtMidi, Linux and Raspberry Pi port, 16-bit engine, fixture (device) support.

This page explains how to get the sources, build them and propose your changes. All contributions are welcome: bug fixes, new features, documentation, translation, testing.

Talk with us

To report a bug, ask a question, suggest an idea or let us know you are working on something, head to the forum:

  • https://forum.arpschuino.fr/viewforum.php?f=24

For a bug, give the WhiteCat version (shown at startup), your system (Windows 10/11, Linux, Raspberry Pi), what you were doing, what you expected and what happened. If you cannot build, attach the full output of build.bat: it is often a small environment detail, quickly fixed.

Getting the sources

The code is on GitHub: https://github.com/arpschuino/whitecat_crossplateform 

git clone https://github.com/arpschuino/whitecat_crossplateform.git
cd whitecat_crossplateform

Two main branches:

  • 0.9.2 (default branch): the stable version. Bug fixes start from here.
  • 0.10-devices: the development version (16-bit patch, devices and GDTF import, Control Fixtures, 16-bit engine). New features start from here.

Warning: a show saved with 0.10 does not reopen correctly with 0.9.2. Keep separate folders for each version.

Building on Windows

The compiler, the libraries and the runtime files are not in git: they come in a build kit (about 80 MB), which a script downloads and installs for you. 

setup_windows.bat
build.bat

The executable is built in whitecatbuild\build\white_cat_for_mingw\Whitecat_Crossplatform.exe, next to the DLLs, fonts and configuration.

The kit installs:

  • tools/MinGW/: the TDM-GCC 5.1.0 compiler (32 bit). Do not use another compiler: the provided libraries are built for this one.
  • whitecatlib/: SDL2 2.30.8, SDL2_ttf 2.24.0, SDL2_image 2.8.8, SDL2_mixer 2.8.1, RtMidi 6.0.0, OpenCV 2.4.8, libharu, zlib, FTDI D2XX. It is a reduced copy of Christoph's whitecatlib repository, completed with SDL2 and RtMidi.
  • whitecatbuild/build/white_cat_for_mingw/: DLLs, fonts, resources and default configuration.

Good to know:

  • setup_windows.bat never overwrites an existing file: your settings (user/) and your shows (saves/) are kept if you run it again.
  • If you had already rebuilt whitecatlib/ or tools/ yourself, rename them before running the script: otherwise it would complete your version instead of installing the kit's.
  • Offline: download the kit from the Releases page, put the zip next to setup_windows.bat, then run the script.
  • With VSCode: open the project folder, Ctrl+Shift+B builds, F5 starts the debugger.

Building on Linux

On Linux (x86_64 or Raspberry Pi), the libraries come from the system packages: 

sudo apt install build-essential libsdl2-dev libsdl2-ttf-dev libsdl2-image-dev libsdl2-mixer-dev \
                 libhpdf-dev libasound2-dev libftdi1-dev zlib1g-dev
make -f Makefile.linux -j4

The executable is built in whitecatbuild/build/linux/Whitecat_Crossplatform. Copy the runtime folders (Fonts/, gfx/, ressources/, user/…) next to it, from the Linux archive of the latest release. On Linux, file name case matters: use the names from the Linux archive.

Finding your way in the code

All the code is in Src/. A few entry points:

  • MAIN.cpp: initialization and main loop.
  • graphics_backend.h: the SDL2 layer that replaces Allegro and OpenLayer (window, drawing, keyboard, mouse).
  • midi_backend.h (RtMidi), audio_backend.h (SDL2_mixer, OGG/FLAC players), wc_platform.h (Windows / Linux differences).
  • save_show.cpp: saving and loading shows.
  • The *_core.cpp files hold the logic of a window, the *_visu.cpp files its drawing (cue list, faders, bangers, grid players, patch…).

The legacy code is dense, with many global variables. Three pitfalls to know:

  • Precompiled header: if you change graphics_backend.h, or a header included by whitecat.h, delete Src/wc_tus.h.gch before building again.
  • New global variable in graphics_backend.h: follow the WC_SKIP_GLOBALS pattern (extern declaration in the files, definition in MAIN.cpp). Otherwise each file would get its own copy, without any build error.
  • Switching branches (0.9.2 ↔ 0.10-devices): delete the *.o and *.d files in whitecatbuild/build/white_cat_for_mingw/ and the .gch file, otherwise the executable would mix both versions.

Proposing a change

We use a fork and a pull request:

  1. On GitHub, click Fork at the top of the repository page: you get your own copy.
  2. Clone your fork, and declare the original repository as upstream: 
    git clone https://github.com/YOUR_ACCOUNT/whitecat_crossplateform.git
cd whitecat_crossplateform
git remote add upstream https://github.com/arpschuino/whitecat_crossplateform.git
  3. Create a branch for your work, from 0.9.2 for a fix, or from 0.10-devices for a new feature: 
    git checkout -b fix-crossfade-display upstream/0.9.2
  4. Work, build, test. Commit in small steps: 
    git status
git add Src/modified_file.cpp
git commit -m "Cue list: fix crossfade display after GO BACK"
  5. Before proposing, get the latest changes from the original repository: 
    git fetch upstream
git rebase upstream/0.9.2
  6. Push your branch to your fork, then open a pull request on GitHub: 
    git push origin fix-crossfade-display

To make a pull request easy to review:

  • one topic per pull request, with short commits and a message that says what changes and why;
  • describe how you tested (Windows, Linux, with which DMX or MIDI hardware);
  • do not commit whitecatlib/, tools/ or your shows: they are excluded by .gitignore, leave them out;
  • for a large change, talk about it first on the forum: we will avoid working twice on the same thing.

Your contributions are released under the same license as WhiteCat, the GNU GPL v2.

Commenting the code (Doxygen)

Part of the code is commented in the Doxygen format, which generates technical documentation from the comments. For a new function, please follow this format: 

/**
 * \brief Plays an audio file from a given time
 * \param file      full path of the file (wav, mp3, ogg, flac)
 * \param startTime start of playback, in milliseconds
 * \return number of the file in the playlist, -1 on error
 */
int play(const char* file, long startTime);

Comments starting with // remain ordinary comments, ignored by Doxygen. To generate the documentation (in docAPIwhitecat/, next to the repository): 

cd Src
doxygen Doxyfile

A bit of history

WhiteCat went open source in June 2013. Georges Khaznadar, Anton Langhoff and RuiSerge then set up the Git repository, the Doxygen conventions and the first contribution rules, on Christoph Guillermet's repository. This page replaces their 2013-2014 pages, made obsolete by the modernization of the software, but the spirit remains the same: working together without ever losing a version that works.
